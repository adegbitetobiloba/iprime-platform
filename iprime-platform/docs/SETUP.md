# iPrime setup guide

Works on Windows, macOS and Linux. Windows-only notes are marked.

## 1. Push this scaffold to GitHub

```bash
git clone https://github.com/adegbitetobiloba/iprime-platform.git
cd iprime-platform
# copy everything from this bundle into the folder (keep the hidden .github folder and .gitignore)
git add .
git commit -m "chore: initial iPrime scaffold"
git branch -M main
git push -u origin main
```

Then set the repo back to **Private** (Settings > General > Danger Zone) if it is still public.

## 2. Run the backend locally

```bash
cd backend
npm install
cp .env.example .env        # Windows PowerShell: Copy-Item .env.example .env
```

Edit `backend/.env`:
- `MONGO_URI` - from MongoDB Atlas (step 3).
- `JWT_SECRET` - generate with `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`.
- Leave `NODE_ENV=development`: OTP codes print in the terminal, so email setup is not needed locally.

```bash
npm run dev      # http://localhost:3000/health
npm test
```

Commit the generated `backend/package-lock.json`, then change `npm install` to `npm ci` in `.github/workflows/ci.yml`.

## 3. Database (MongoDB Atlas)

1. Create a new project **iprime** and a free cluster (choose a region close to Nigeria, e.g. Europe).
2. Database Access > add a user (e.g. `iprime_app`) with a strong password and **read/write on the iprime database only**.
3. Network Access > allow access from Render. The free plan has no fixed IP, so use `0.0.0.0/0` and rely on the strong password.
4. Connect > Drivers > copy the connection string. Add `/iprime` as the database name before the `?`.
5. The string goes **only** in `backend/.env` and in Render's environment settings. Never in the frontend or in Git.

Do not reuse the FVIC cluster, user or database.

## 4. Backend on Render

1. Render dashboard > New > **Blueprint** > select `iprime-platform`. It reads `render.yaml` and creates the service `iprime-api` (separate from the FVIC service).
2. Fill in the prompted variables: `MONGO_URI`, `CORS_ORIGINS` (your Netlify URL, step 5), `BREVO_API_KEY`, `EMAIL_FROM`. `JWT_SECRET` is generated by Render.
3. After deploy, open `https://<service>.onrender.com/health`. It should return `{"status":"ok","db":true}`.

Free-plan services sleep when idle; the first request after a while can take about a minute.

## 5. Frontend on Netlify

1. Netlify > Add new project > Import from GitHub > `iprime-platform`. Use a **new** site (suggested name `iprime`). `netlify.toml` provides the build settings and SPA routing.
2. Site configuration > Environment variables: `VITE_API_URL=https://<your-iprime-api>.onrender.com/api`.
3. Add the final Netlify URL to `CORS_ORIGINS` on Render and redeploy the backend.

## 6. Email (OTP)

Create a Brevo account, verify a sender address, create an API key, then set `BREVO_API_KEY` and `EMAIL_FROM` on Render. Until a provider is configured, production sign-up reports an email failure clearly instead of pretending to send.

## 7. First administrator

```bash
cd backend
ADMIN_EMAIL=you@example.com ADMIN_PASSWORD='a long passphrase' npm run create-admin
```
(Windows PowerShell: `$env:ADMIN_EMAIL="..."; $env:ADMIN_PASSWORD="..."; npm run create-admin`)

## Environment variables

| Variable | Where | Required | Notes |
|---|---|---|---|
| `MONGO_URI` | backend | yes | Atlas connection string |
| `JWT_SECRET` | backend | yes | 32+ characters |
| `CORS_ORIGINS` | backend | production | comma-separated frontend URLs |
| `NODE_ENV`, `PORT` | backend | no | `production` on Render |
| `BREVO_API_KEY`, `EMAIL_FROM` | backend | for OTP email | or Gmail `EMAIL_USER`/`EMAIL_PASS` |
| `AUTH_RATE_LIMIT` | backend | no | default 30 per 15 min per IP |
| `VITE_API_URL` | frontend | yes | public API URL only |

## Workflow

`main` is stable. Work on `feature/<name>`, open a pull request, let CI pass, merge. Render deploys only when checks pass.
